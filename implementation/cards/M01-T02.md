## Goal

Determine whether the bundled runtime can be mapped deterministically to an `openai/codex` source revision and inventory the Desktop/app-server protocol surface whose drift can make a replacement runtime incompatible.

## Scope

Included: runtime version/build/revision signals from T01; release/tag/commit mapping methods; app-server schema/protocol/version/feature-handshake surfaces; Desktop invocation expectations visible in current Community/upstream artifacts; explicit mapping verdict and drift risks.

Excluded: custom runtime build, protocol modification, feature implementation.

## Authoritative inputs

T01 evidence; current exact official Desktop/runtime baseline; current `openai/codex`; relevant app-server protocol schemas/source; R6/R8; Master Plan M01.

## Refresh Gate

Refresh `openai/codex` and any Desktop baseline changed since T01. If T01's official package tuple is no longer the intended tested baseline, reconcile or block rather than mixing identities.

## Expected outputs

`implementation/evidence/M01-T02_SOURCE_PROTOCOL.md` containing mapping procedure/verdict, exact source candidates when determinable, protocol inventory and drift-sensitive compatibility surfaces.

## Acceptance criteria

- source mapping is classified `deterministic`, `safely derivable by documented procedure`, or `unavailable`;
- no guessed commit is promoted as baseline;
- protocol/app-server compatibility surfaces relevant to Desktop startup/session/turn/tool behavior are documented;
- any version/schema negotiation or absence thereof is explicit;
- inputs needed by the later compatibility gate are identified.

## Required evidence/checks

Exact runtime identity from T01, GitHub source/tag/commit evidence, current protocol/schema/source references, and reproducible comparison procedure.
